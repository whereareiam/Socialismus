`commands` holds how commands behave as a whole, under `behavior`, and the definition of each command, under `commands`.

## behavior

`behavior` controls the command manager rather than any one command definition.

### useBrigadier

<Badge type="warning">Advanced</Badge>

- Takes: `true` or `false`
- Current default: `false`
- Affects: whether the legacy Paper command manager registers native Brigadier support when that capability exists

This is mainly relevant on Paper-side setups where the underlying Cloud command manager exposes Brigadier support.

### useAsyncCompletions

<Badge type="warning">Advanced</Badge>

- Takes: `true` or `false`
- Current default: `true`
- Affects: whether asynchronous command completions are registered when the current command manager supports them

### help.commandsPerPage

- Takes: a whole number, at least `1`
- Current default: `7`
- Affects: how many commands one page of `/socialismus help` lists

### pagination

`pagination` decides when the page line under `/socialismus help` and its arrows are shown. Its texts stay in `messages.yml`, under `commands.pagination`.

- `showIfOnePage`: whether the page line is shown when all commands fit on one page; default `false`
- `showPreviousOnFirst`: whether the previous arrow is shown on the first page, where it opens the first page again; default `false`
- `showNextOnLast`: whether the next arrow is shown on the last page, where it opens the last page again; default `false`

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
behavior:
  useBrigadier: false
  useAsyncCompletions: true
  help:
    commandsPerPage: 7
  pagination:
    showIfOnePage: false
    showPreviousOnFirst: false
    showNextOnLast: false
```
  </Tab>
  <Tab value="JSON">
```json
{
  "behavior": {
    "useBrigadier": false,
    "useAsyncCompletions": true,
    "help": {
      "commandsPerPage": 7
    },
    "pagination": {
      "showIfOnePage": false,
      "showPreviousOnFirst": false,
      "showNextOnLast": false
    }
  }
}
```
